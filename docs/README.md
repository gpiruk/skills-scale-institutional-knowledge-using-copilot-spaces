# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management docs. This folder collects the team's processes, roles, artifacts, and checklists so new teammates and stakeholders can quickly find the guidance they need to run and contribute to projects.

## Quick Start

New to OctoAcme project management? Start here:

1. [Project Management Overview](./octoacme-project-management-overview.md) — Read the principles, core roles, key artifacts, and the high-level lifecycle.
2. [Roles & Personas](./octoacme-roles-and-personas.md) — Learn the responsibilities and communication patterns for Developers, Product Managers, Project Managers, QA, and Stakeholders.

## Core Project Phases

1. [Project Initiation](./octoacme-project-initiation.md) — Create a Project One‑pager, confirm success metrics, and decide whether to move into planning.
2. [Project Planning](./octoacme-project-planning.md) — Prioritize the backlog, estimate work, define Definition of Done, and create a release plan.
3. [Execution & Tracking](./octoacme-execution-and-tracking.md) — Day‑to‑day delivery practices: project board workflow, PR conventions, CI, testing, and reporting cadence.
4. [Risks & Communication](./octoacme-risks-and-communication.md) — How to capture, escalate, and communicate risks across teams and stakeholders.
5. [Release & Deployment](./octoacme-release-and-deployment.md) — Pre‑release criteria, deployment checklist, rollback and incident playbook.
6. [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md) — Capture learnings, track action items, and improve processes.

## Navigation

- Use this README as the single entry point for OctoAcme project management guidance.
- Each document contains a checklist and templates. Look for checklists at the bottom of each page (e.g., Initiation Checklist, Planning Checklist, Execution Checklist).
- For project-specific artifacts, store the Project Charter and process‑specific docs inside the project repository (recommended path: `docs/` or `.copilot/` for Copilot Spaces context).

## How to use these docs

- Keep the Project One‑pager and the Definition of Done updated in the project repo.
- Add or update process docs here when practices change; use clear commits and link the change to an issue where appropriate.
- If you want Copilot Spaces to surface project context, add process-specific files into `.copilot/` inside the project repo.

## At a glance

OctoAcme follows a customer‑first, iterative approach with clear ownership and data‑informed decision making. Projects move through a defined lifecycle (Initiate → Plan → Execute → Release → Close) supported by regular cadences (daily standups, weekly syncs, demos) and documented escalation paths. Use the linked guides above for templates, checklists, and role responsibilities.
